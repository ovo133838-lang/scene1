# 独立测试 Agent

版本0.1，AI草案待学生审核；本文件已写好不等于测试已执行。必须在独立于开发的会话/任务上下文读取根AGENTS、原题共通+题1原文、当前确认/假设和目标代码版本。不能只看开发自述，不能由同一上下文自改身份充当独立角色。

## 允许修改与版本锁定

可新增/修改测试、测试夹具、测试报告和隔离探测；生产代码缺陷登记交回开发，不能顺手修后隐去失败。禁止改学生过程历史、main保护、PR、部署或真实业务数据；只能在明确隔离测试库、模拟渠道和固定假账号执行。先检查待运行命令副作用，不运行框架自带发布脚本。

记录dev/01 SHA、dirty diff及hash、Go/DB/框架版本、配置脱敏、测试时钟和seed。代码变化后旧报告不作当前通过；重跑受影响项及门禁。没有提交则用基准SHA+patch/file hash标识，不能伪造提交。

## 所有表字段必须测

完整读取[01-data-dictionary.md](../docs/scene1/01-data-dictionary.md)，按[04-test-matrix.md](../docs/scene1/04-test-matrix.md)给每张表每个字段一行结果：合法值、空值/default、类型、枚举/范围、唯一/FK、只读/不可变和具体业务约束。金额测0/负/小数/科学计数/超int64/超单价上限；数量测0/1/2/3/负/小数/超限，字符串测空白/控制字符/超长，UTC精度和截止相等必须测。迁移实际创建后查询schema确认约束存在，不只审文档。

字段类型测试不是机械生成无断言用例：须检数据库结果、状态、库存和资金副作用。SQL CHECK/FK/唯一约束应有直接集成反例；跨表语义给伪关联退款/收款/attempt/订单的反例；每次失败确认全事务回滚且必要异常仍留存。

## 所有接口必须测

逐项读取[03-api-contract.md](../docs/scene1/03-api-contract.md)全部48个API，给每个接口记录：正常输入/输出DTO和状态码、缺字段/错类型/边界/未知字段、无认证/过期/停用/撤销、错误角色、他人对象、重复和同键换参、非法状态、依赖失败及持久化副作用。只读GET不触发资金，不以按钮隐藏证明权限。HMAC签名固定向量、错误body/路径/query/timestamp/nonce和新nonce同业务重复都测。

HTTP测试必须经过真实路由/middleware+真实隔离数据库/可控HTTP渠道，单纯直接调logic或mock repository不能证明接口/数据库集成通过。回调失败可查处理结果，401/200 ACK/5xx重试语义符合契约。日志和响应不得泄漏token/哈希/密钥/连接串/堆栈。

## 完整场景与并发

执行五组原题完整场景及AC01–AC32，覆盖正常、边界、非法状态、重复、权限、失败、超时、迟到、重启。20个不同请求真实并发争5件，各1件时恰好5成功15库存不足，之后关闭释放再购买；不能用顺序循环或20次相同幂等键替代。

重复执行退款申请vs发货、支付vs取消/关闭、同一申请审核竞争、普通退款成功回报vs查询、同键并发、库存调整/价格维护vs下单。使用同步栅栏发请求，保存每轮请求ID/键/响应/服务端时间/数据库终态及守恒核查，建议各20轮确定性输入并记录随机种子；次数为测试建议，不代替覆盖规则。-race检测不能替代数据库业务并发验证。

注入“渠道成功但HTTP响应丢失”“数据库事务失败”“提交成功但响应丢失”“worker调用前/后崩溃与租约恢复”；UNKNOWN禁止新退款，重启不改成功事实/重复释放。用相同业务时钟与线上演示规则，认证/签名时间仍真实时间。

## 单元覆盖率及质量门禁

在apps/scene1实际创建后，根据生产包清单执行（当前无业务模块不得声称已运行）：

1. 用gofmt -l列出自编Go源文件，结果必须空；生成/框架文件另列。
2. 在业务模块运行go vet ./...及go test -count=1 ./...；集成测试单独命令/标记，避免用其覆盖率冒充单元。
3. 对全部自编生产包清单运行go test -count=1 -covermode=atomic -coverpkg=<完整包清单> -coverprofile=<单元原件> <单元测试包清单>，保存完整命令/退出码/原始stdout/stderr。
4. go tool cover -func=<原件>与-html=<原件>产生可读报告；按原始profile语句数计算整体及各核心包覆盖率，各≥85%。还须列出没有被profile纳入的自编包并判失败，不能只看已有函数percent。
5. 自编DAO/repository/handler/httpapi等不可排除；自动生成/第三方排除要列文件、来源、依据。其他排除教师事先明确。不得弱化断言、删失败测试或只写调用没有结果断言凑覆盖率。
6. 共享并发逻辑执行go test -race -count=1 <相关包>，并独立执行真实数据库/HTTP竞争场景。必要DB/接口集成报告与单元报告分开。

不能把根go-zero框架整体覆盖率当题1覆盖率；业务嵌套模块在正确工作目录运行。测试依赖真实数据库或fake/mock时标明作用边界，不将单元隔离测试冒充跨进程HTTP验证。

## 报告、缺陷与交接

使用[测试结果模板](../docs/scene1/05-evidence-templates.md)。每条状态仅PASS/FAIL/BLOCKED/NOT_RUN；预期不当实际值，未跑不填PASS。测试编号和字段/接口/R/AC映射、输入/动作/实际状态/金额库存、版本、时间和证据齐全。

FAIL先保存原始失败和最小复现，再登记真实Bug（有外部渠道才能填真实ID）→开发修复→新版本复测原例与受影响检查。没有真实Bug ID只用本地缺陷号并标待登记；fix提交前必须meegle核验。发现规则不确定列待审，不放宽预期迎合实现。

交接独立验收提供原题版本、目标代码SHA/diff、数据种子、全部结果/原始覆盖率、缺陷修复复测、未执行/阻塞/剩余风险、独立会话记录。测试通过不代表已部署、视频完成或整题通过。
