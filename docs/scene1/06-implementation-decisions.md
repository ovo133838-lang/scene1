# 实施决定 0.2（2026-11-12）

用户本轮已授权补齐准备并开发，取代0.1中“仅生成文档”的当时任务范围。仍保留AI协助起草来源，不代签学生审核；A项以下按补齐授权采用为设计决定，非六项U之外的用户逐项确认。

- 采用 MySQL 8.0 / InnoDB，使用已安装本机程序；最初MySQL80未启动时使用本题隔离实例13306；用户启动本机服务后已迁回3306，专用辅助实例已停止。Redis非必要，不引入。UUID→char(36) ascii，timestamptz→datetime(6)统一UTC，jsonb→json，部分唯一索引→可空生成列+唯一索引；字段原名、含义和DTO不变。商城和模拟渠道用两个独立schema、独立账号。
- 小规模教学系统所有写事务先锁各自demo_clock单行（mock使用技术表runtime_lock），然后按业务表处理；数据库跨进程串行裁决，无进程内互斥依赖。吞吐不是本题目标。读用一致快照，HTTP调用在事务外；不持锁等网络。此项取代0.1逐订单锁的优化建议。
- 采用审核清单A01/A03–A12保守方案：锁内时点、B=20000分/8件、写幂等、异常独立查实、审核不可反转、未知不新请求、可信Bearer、统一教学时间、资金按逻辑笔统计。
- 追加schema_migrations（version/checksum/applied_at）、mock.runtime_lock（id）为迁移及渠道并发技术表，不属于256业务字段；不修改任何已有框架源码。
- go-zero rest承载商城，独立HTTP模拟支付服务；自编SQL仓储/业务/传输分层。OpenAPI为接口入口，以contract-index逐条映射。48接口逐项核查，未实现不得声称完成。
- 开发自测、独立测试和独立验收分开；本会话不改口冒充独立角色。真实工作项和meegle、部署权限尚缺时不提交发布，继续本地实现与自测。

- 独立验收返修AC-001–004：外部ID限定路径安全ASCII；仓库排序字段不出站；双向key_id分离并采用固定向量；审计与HTTP响应关联ID使用同一请求上下文。属于现有安全/契约要求修正，不扩大业务范围。
