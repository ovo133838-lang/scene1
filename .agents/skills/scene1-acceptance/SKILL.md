# scene1-acceptance

版本0.2，2026-11-12，AI协助编写。学生作者/审核来源仍待真实补充，不能由AI代签。

用途：独立验收题1最终候选版本及交付过程。触发场景：独立测试交接后、修复后重新验收、PR候选或实际主分支发布版本复核；开发自测不能充当独立验收。

输入：原始题集共通要求和题1、用户确认、AGENTS/真实代码及哈希、测试原件与未测清单、隔离环境、部署/PR/过程索引。必须自己读原题与目标代码，不能只读开发总结。

执行步骤：

1. 清点真实字段/路由和生产文件，锁定版本、DB和HTTP地址，检查测试命令副作用。确定验收环境与测试环境分离、可重现，不修改生产代码。
2. 在真实浏览器操作四工作台：运营上架→买家购买付款→仓库登记→买家运单→运营核查；退款申请冻结→客服批准→首败再成功；关闭后迟到款→核实退款。观察失败/禁用原因、页面状态与DB终态。保存关键截图和动作记录，不能用主开发截图或API调用冒称独立浏览器验收。
3. 真实HTTP同步20请求抢5件、弃单释放再买、申请vs发货、重复通知与越权；并发可由程序驱动，浏览器查看对应结果，并标清两种证据。
4. 检查快照、10分钟边界、拒绝可重提、UNKNOWN冻结先查、迟到不重复释放、异常不消失、重启后事实保留。核对字段/API矩阵中每个适用维度，不把静态清单当实际通过。
5. 复跑fmt/vet/单测与race，确认全部自编生产包入profile，整体及各核心包≥85%。核对原始失败、开发修复与新哈希复测关系。
6. 对照共通要求逐条检查需求/原型/计划、三角色独立上下文、两个Skill结构及调用、学生审核和指导、全过程导出、Git真实ID/meegle/PR/main保护、流水线实际部署SHA/URL/冒烟/回退、学生讲解视频与群记录。没有原件保留待补证。

输出格式：`要求编号 / 原题位置 / 当前真实字段或接口 / 实际动作 / 预期 / 实际 / PASS|FAIL|BLOCKED|NOT_RUN / 源码哈希 / 截图或原始输出路径`；另给五场景结论、DB守恒、缺陷及复测、全部尚缺交付物和所需条件。

失败处理：保留首败、场景数据与复现步骤，交开发修复；变更后复验原例和受影响检查，不自行改生产/减断言。依赖或人工材料缺失如实BLOCKED/NOT_RUN，未运行不判PASS；不能补造学生作者、学生指导、部署或视频。

完成标准：最终候选哈希对应的全部业务/质量验收通过；全部适用共通门禁有真实证据，才可判整题完成。允许分别给“本地业务范围通过”和“整题待补”，不能混淆。正式发布仍依PR和主分支流水线门禁执行。
